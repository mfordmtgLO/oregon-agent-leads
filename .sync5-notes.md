# Sync 5 review — "Add principal broker records to Oregon directory sync"

Commit e75059e (incoming from GitHub) does two things:

1. `server/syncExport.ts` — broker links changed from agent-list lookup to a new
   `?principalBroker=<encoded name>` deep link. Brokers are now emitted as their own
   `recordType: "principal_broker"` records with `rankKind: "office"`, negative stable
   ids, deduped case-insensitively, sorted by office rank. Payload gains
   `topAgentCount` / `principalBrokerCount`.
2. `client/src/pages/Dashboard.tsx` — derives a principal-broker directory client-side and
   merges it into the Agent Index list (`directoryRecords`), supports `?principalBroker=`
   deep links, heading now reads "60 top agents + 37 principal brokers".

## Observations to raise with the user (NOT bugs I introduced)
- Broker cards in the Agent Index reuse agent-shaped fields, so office buyside numbers
  render under agent labels: e.g. Jason Walchli shows "1000 SIDES '25" (that is the office
  buyside estimate, not his personal sides) and "$13.55M VOLUME '25" carried from an agent
  row. Jim Remley shows "854 SIDES '25 / $46.39M".
- Broker cards inherit the co-located agent's `websiteBioUrl` / `zillowUrl`, so links can
  point at an unrelated agent (Jim Remley's card links to Shannon Mahar-Krug's Zillow;
  Geoff O'Neill's card links to Alex Aaronson).
- Broker rank badges collide with agent rank badges in the same list (two "No. 1", two
  "No. 2"), because agent RealTrends rank and office buyside rank share the badge slot.
- The office-estimation methodology text lands in the notes textarea on broker cards,
  which looks like a saved personal note.
- Search still filters `agents` only (`list = agents.filter(...)` inside the memo), so
  typing a query drops all broker records from the results. Clearing the query brings
  them back. Likely unintended.
- Sidebar territory pill still reads "Oregon · 60" while the heading says 97 records.
